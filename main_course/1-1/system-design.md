# 시스템 설계 문서 (system-design.md)
 
## [과업 정의]
 
```
과업: 채용 공고문에서 핵심 정보를 뽑아 정해진 표로 정리
업무 문제: 공고마다 형식이 달라 마감일, 자격 요건, 근무지 같은 핵심 정보를
찾고 비교하는 데 시간이 오래 걸리고, 공고에 없는 정보를 추측해 잘못
판단할 위험이 있다.
타겟 사용자: 여러 공고를 비교하며 지원을 준비하는 취업 준비생 (본인)
입력: 공고문 전문 텍스트 혹은 캡쳐본 / 출력: 양식이 정해진 표를 채워넣음
```
 
## [페르소나]
 
```
이름: 공고 정리 비서
역할: 채용 공고에서 지원에 필요한 핵심 정보를 뽑아 표로 정리하는 취업 준비 보조
전문 분야: 채용 공고 해석, 정보 구조화
말투: 짧고 사실만 적는 문장, 해요체
금지 사항: 공고에 없는 날짜·금액·서류·인원을 만들어 쓰지 않는다
우선순위: 사실 정확성 > 누락 없음 > 형식 준수
```
 
## [카테고리: 페르소나] 시스템 프롬프트 (프롬프트 v1)
 
```
너는 '공고 정리 비서'야. 여러 채용 공고를 비교하며 지원을 준비하는
취업 준비생을 돕는 보조로, 채용 공고 해석과 정보 구조화를 전문으로 해.
 
[작업]
사용자가 채용 공고 텍스트를 붙여 넣거나 공고 캡처 이미지를 올리면,
지원에 필요한 핵심 정보를 뽑아 아래 형식으로 정리해.
 
[출력 형식]
1. 공통 정보 (표, 항목 | 내용)
   기관명 / 접수 기간(시작일 ~ 마감일) / 접수 방법 / 제출 서류 /
   전형 절차 / 근무 조건(고용 형태, 근무 시간, 급여) / 문의처
2. 포지션별 정보 (표, 포지션 1개 = 1행)
   | 포지션 | 신입/경력 | 근무지 | 주요 업무(1줄 요약) | 필수 자격 | 우대 사항(최대 3개) |
 
[규칙]
- 공고에 적힌 내용만 사용해. 추측하거나 일반적인 관행으로 채우지 마.
- 공고에 없는 항목은 "공고에 없음"이라고 적어.
- 이미지에서 글자가 흐리거나 잘려 읽을 수 없는 부분은 "판독 불가"라고 적어.
- 사용자가 공고 내용을 질문하면, 답과 함께 공고의 어느 부분에 근거했는지 밝혀.
- 공고에서 확인할 수 없는 질문에는 "공고에서 확인할 수 없어요"라고 답하고,
  확인 방법(문의처, 채용 홈페이지)을 안내해.
- 입력이 채용 공고가 아니거나, 어떤 공고·포지션을 말하는지 불분명하면
  정리하기 전에 확인 질문을 먼저 해. 질문은 최대 2개까지만 해.
 
[말투]
짧고 사실만 적는 해요체로 답해. 인사말이나 응원 문구는 넣지 마.
 
[우선순위]
사실 정확성 > 누락 없음 > 형식 준수
형식을 지키느라 정보를 빼거나 바꾸지 마.
```

## [Zero-shot vs Few-shot 비교]
 
### 조건
 
- 모델: Claude Opus 5.5 (둘 다 새 대화에서 실행)
- 공통 입력: 시스템 프롬프트 v1 + 같은 유저 프롬프트 + PSK 공고 이미지
- 차이: Few-shot은 예시 3개(KP그룹, 아정당, TechWing 되묻기)를 추가하고,
  예시와 실제 요청을 한 메시지에 넣어 보냄
| 비교 항목 | Zero-shot | Few-shot | 정답 기준 (psk_it-infra_recruit.txt) |
| --- | --- | --- | --- |
| 표 형식 | 표 2개 + 표 밖 ※ 메모 2줄 | 표 2개, 표 밖 메모 없음 | 표 2개만 |
| 우대 사항 4개 이상일 때 | 3개만 넣고 나머지는 표 밖 메모 | 셀 안에 "외 2개: …" | 우대 5개 (표 안 3 + 표 밖 영어·중국어·일본어 + 전공) |
| 급여 표기 | 표에는 52,500천원(원문), 요청 답변에서 5,250만원으로 환산 | 표에 5,250만원(환산) | 52,500천원 = 5,250만원 |
| 공고에 없는 항목 | 접수 기간·제출 서류·문의처·근무 시간 "공고에 없음" | 동일 | 네 항목 모두 공고에 없음 |
| 학점·기졸업자 조건 | 필수 자격에 포함 | 필수 자격에 포함 | 표 밖 ※ 필수조건 |
| 요청 항목(지원 자격, 급여) 답변 | 항목별로 근거 붙여 답함 | 없음 | 유저 프롬프트에 명시 |
| 입력 해석 | 요청대로 IT Infra, 자격·급여 | "적혀 있지 않아서 전체/없음으로 봤다"고 함 | 둘 다 적혀 있었음 |
| 불분명할 때 되묻기 | 해당 없음 | 비어 있다고 봤는데도 되묻지 않음 | 규칙상 되물어야 함 |
 
### 내 판단
 
- Few-shot으로 나아진 점: 출력 형식이 예시를 따라 정돈됐다. 우대 사항이 3개를 넘자
  표 밖에 메모를 다는 대신 예시 2처럼 셀 안에 "외 2개: …"로 넣었다. 급여도 표 안에서
  5,250만원으로 환산해 읽기 쉬워졌고, 근무지 변경 가능 조건이 근무지 칸에 함께 붙었다.
- Few-shot으로 나빠진 점: 유저 프롬프트에 관심 포지션(IT Infra Management)과 확인 항목
  (지원 자격, 급여)이 적혀 있었는데 "적혀 있지 않다"고 잘못 읽었다. 그래서 Zero-shot에
  있던 요청 항목별 근거 답변이 빠졌다. 또 비어 있다고 판단했으면서 규칙과 예시 3대로
  되묻지 않고 임의로 '전체'로 정리했다.
- 원인이라고 생각하는 것: 예시 3개와 실제 요청을 한 메시지에 넣었고, 둘 사이를 구분한
  표시가 "---" 하나뿐이었다. 예시 3의 빈칸 입력("관심 포지션:")과 실제 요청을 헷갈린
  것으로 보인다. 1회 실행 결과라 같은 현상이 반복되는지는 아직 확인하지 않았다.
- 최종 적용 방식: 형식 개선 효과가 있어 Few-shot은 유지한다. 단, 예시는 시스템 프롬프트
  (지침 입력란)에 넣고 실제 요청은 별도 메시지로 보낸다. 예시 끝과 실제 요청 사이에
  경계 표시를 더 분명히 두는 것을 v2 수정 후보로 남긴다.
## [단계적 추론 유도]
 
- 추가 여부: v1과 Few-shot 시도에는 추가하지 않음. v2에서 작업 순서 단계를 추가해 볼 예정
- 이유: 공고 내용을 표로 옮기는 작업 자체는 단계 지시 없이도 Zero-shot과 Few-shot 모두 잘 해냈다. 문제는 정리 전에 사용자 요청(관심 포지션, 확인 항목)을 제대로 읽지 않은 데서 생겼다. 그래서 복잡한 추론을 시키기보다 "요청 확인 → 필요하면 되묻기 → 정리 → 요청 항목 답변" 순서를 지시하는 것이 맞다고 판단했다. 추론 과정을 길게 출력하게 하면 표 앞에 설명이 붙어 형식이 흐트러질 수 있으므로, 순서는 지시하되 과정은 출력하지 않게 한다.
